# Java高并发系统完整设计方案
整体思路：**架构分层扩容 → 瓶颈拆分削峰 → 锁与线程模型优化 → 缓存&异步兜底 → 兜底限流熔断 → 监控落地**，从宏观架构到Java代码细节逐层落地。

## 一、宏观架构：横向扩容，消除单点瓶颈
### 1. 接入层（网关层）
目标：承接海量请求、负载均衡、流量入口管控
1. **Nginx 集群**
    - 四层TCP负载均衡+七层HTTP转发，做**多实例集群**，杜绝单点；
    - 静态资源缓存、SSL卸载、前置限流、IP黑名单；
    - 配置长连接复用，减少TCP握手损耗。
2. **业务网关（SpringCloud Gateway/APISIX）**
    - 路由分发、鉴权、参数校验、统一日志、灰度发布；
    - 前置限流、熔断拦截，无效请求不打入后端服务。

### 2. 应用服务层：微服务拆分 + 无状态化
高并发核心前提：**服务必须无状态**
- 禁止在JVM内存存放会话、登录信息，会话统一存入Redis；
- 服务多实例部署，可随时扩容缩容，弹性伸缩；
- 按领域拆分微服务：订单、支付、商品、用户，**拆分热点隔离**，避免一个模块拖垮整体。

### 3. 中间件分层，解耦同步阻塞
| 场景 | 中间件 | 作用 |
| ---- | ---- | ---- |
| 异步削峰 | RocketMQ/Kafka | 同步转异步，秒杀、消息通知、日志异步落地 |
| 热点缓存 | Redis集群 | 挡DB90%查询压力，热点数据内存访问 |
| 分布式协调 | Nacos/Etcd | 配置中心、服务注册发现、分布式锁 |
| 数据库 | MySQL主从、分库分表 | 拆分写入压力，读写分离 |

## 二、数据库优化：高并发最大瓶颈
### 1. 读写分离
- 1主N从：主库只写，从库承担所有查询；
- Java端使用MyBatis/Sharding-JDBC自动路由读写。

### 2. 分库分表
- 水平分表：订单、流水按用户ID/时间分片，单表控制在**2000w以内**；
- 垂直分库：拆订单库、用户库、商品库，隔离写入竞争；
- 分片中间件：Sharding-JDBC（客户端无额外组件）优先。

### 3. SQL与索引强制规范
1. 禁止`select *`、禁止大事务、禁止深分页`limit 100000`；
2. 热点更新：库存扣减使用`update stock set num=num-1 where id=xx`，避免Java查询再修改；
3. 索引：热点查询命中唯一索引，杜绝回表、索引失效；
4. 大事务拆分：长事务会拉长锁持有时间，大幅降低并发。

### 4. 兜底方案
- 历史数据归档到离线库，只保留近3个月热点数据在线；
- 频繁统计、报表不查MySQL，走Redis、ES离线计算。

## 三、缓存体系：多级缓存层层拦截请求
### 1. 多级缓存架构
`本地缓存(Caffeine) → Redis分布式缓存 → MySQL`
1. **JVM本地缓存（Caffeine优先）**
    高性能内存缓存，毫秒级访问，存放固定不变热点（商品基础信息、配置）；
    特点：无网络IO、极高并发，缺点：数据不一致，适合弱一致性场景。
2. **Redis集群**
    主从+哨兵/Redis Cluster分片，热点Key打散；
    缓存预热、缓存击穿/雪崩/穿透专项解决。

### 2. 三大缓存问题解决方案
1. **缓存穿透（查不存在数据频繁打DB）**
    布隆过滤器拦截无效key + 空值短期缓存。
2. **缓存击穿（热点key过期瞬间大量请求打DB）**
    互斥锁、永不过期、定时主动刷新热点缓存。
3. **缓存雪崩（大量key同时过期）**
    过期时间随机打散、集群高可用、多级缓存兜底。

### 3. 缓存更新策略
- 普通业务：**先更新DB，再删缓存**；
- 强一致性：分布式锁+串行更新；
- 高并发热点：异步队列更新缓存，放弃实时一致。

## 四、Java 并发内核优化（JVM、线程、锁）
### 1. 线程模型选型
1. **IO密集型（网关、接口、RPC）**：异步非阻塞
    SpringWebFlux、Netty、Reactor，少量线程处理海量连接，替代传统Tomcat同步阻塞；
2. **CPU密集型（计算、解析）**：固定线程池，核心线程数=CPU核心数；
3. **常规Web接口**：Tomcat调参，核心线程200~500，拒绝策略自定义降级。

### 2. 线程池规范
- 禁止手动new Thread，统一使用**业务隔离线程池**；
- IO密集线程池：核心线程 = 2*CPU核心数；
- 拒绝策略不用AbortPolicy，自定义队列积压告警+降级返回。

### 3. 锁优化：尽量少用锁、缩短锁持有时间
#### （1）JVM内置锁优化
1. 优先**无锁**：CAS（Atomic系列、LongAdder）替代synchronized；
2. 锁粒度拆分：分段锁（JDK ConcurrentHashMap）；
3. synchronized：锁对象不要用String常量、Integer包装类，锁范围尽量小；
4. 读写分离锁：读多写少用`ReentrantReadWriteLock`。

#### （2）分布式锁选型（跨JVM并发争抢）
1. **Redis分布式锁**：高性能，普通业务首选，Redisson自动续期防死锁；
2. **Zookeeper锁**：强一致性，性能偏低，适合金融强一致性场景；
3. **MySQL悲观锁**：性能最差，仅极小并发强一致性场景使用。

### 4. JVM高并发调优
1. 垃圾收集器：高并发服务统一用 **G1 / ZGC**，降低STW停顿；
2. 内存：新生代合理扩容，减少频繁YGC；
3. 禁用FullGC：避免大对象直接进老年代、内存泄漏、线程暴涨；
4. 堆外内存：Netty、Redis客户端合理管控，防止堆外溢出。

## 五、异步化：把同步阻塞全部转为异步
### 1. 本地异步
- JDK CompletableFuture 实现接口并行查询；
- Spring @Async 异步线程池做非核心逻辑（短信、日志）。

### 2. 分布式异步（消息队列核心）
适用场景：秒杀下单、订单创建、积分发放、日志采集
1. 削峰：瞬间流量堆积到MQ，后端匀速消费；
2. 解耦：下游服务故障不影响上游主流程；
3. 可靠性：消息持久化、ACK确认、死信队列防丢失；
4. 消费优化：批量消费、多线程消费，提升消费吞吐量。

## 六、流量防护：限流、熔断、降级（高并发系统保命手段）
### 1. 限流（拦住过量流量）
- 网关层限流：Nginx限流、Gateway全局限流；
- 应用层限流：Sentinel、Guava RateLimiter；
- 常用算法：滑动窗口（最稳定）、令牌桶、漏桶；
- 维度：全局限流、IP限流、接口限流、用户ID限流。

### 2. 熔断降级（防止雪崩连锁故障）
组件：Sentinel / Hystrix
- 熔断：下游服务大量失败，直接断开调用，快速失败；
- 降级：高峰期关闭非核心功能（商品详情关闭评论、推荐），保障核心链路；
- 快速失败：超时直接返回兜底数据，不阻塞等待。

### 3. 排队削峰
秒杀场景：请求排队入MQ，前端排队弹窗，不直接打后端。

## 七、经典高并发场景落地示例
### 1. 秒杀系统极简流程
1. Nginx前置限流，拦截恶意请求；
2. Redis预存库存，本地缓存二次拦截；
3. 扣减库存用Redis原子操作，防止超卖；
4. 下单请求丢入MQ异步排队；
5. 消费线程匀速创建订单写入MySQL；
6. 失败订单放入死信队列补偿。

### 2. 接口高并发优化
1. 并行查询：CompletableFuture多线程查多数据源；
2. 热点数据走本地缓存+Redis；
3. 非核心逻辑异步；
4. 慢SQL优化，减少DB耗时。

## 八、高并发系统稳定性保障
1. **监控告警**：Prometheus+Grafana，监控QPS、延迟、GC、线程池、Redis、MySQL指标；
2. **链路追踪**：SkyWalking、Pinpoint定位慢接口、阻塞线程；
3. **压测**：JMeter、Jmeter压测，提前暴露瓶颈；
4. **扩容预案**：容器K8s弹性扩容，高峰期自动加实例；
5. **故障演练**：随机下线节点，验证集群容错能力。

## 九、设计总结（落地优先级）
1. 先架构：无状态+集群扩容、读写分离；
2. 再缓存：多级缓存挡住DB压力；
3. 然后异步：同步转MQ削峰；
4. 接着锁优化：缩小锁范围、无锁优先、分布式锁合理使用；
5. 最后防护：限流熔断兜底、监控告警。
