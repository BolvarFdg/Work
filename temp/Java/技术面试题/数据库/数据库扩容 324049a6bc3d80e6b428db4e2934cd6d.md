# 数据库扩容

1. 什么是数据库扩容

| 扩容方式 | 通俗解释（货车版） | 技术解释（服务器版） |
| --- | --- | --- |
| 纵向扩容（垂直扩容） | 给现有的货车升级：换更大的车厢、更强的发动机，单辆车拉更多货 | 给单台数据库服务器加配置：升 CPU、加内存、换更大的硬盘 |
| 横向扩容（水平扩容） | 不升级现有货车，直接多买几辆货车，多辆车一起拉货 | 不换单台服务器，新增多台服务器节点，分布式分担数据 / 压力 |
1. mysql vs mongo扩容

| 维度 | MySQL 横向扩容 | MongoDB 横向扩容 |
| --- | --- | --- |
| 原生支持 | 几乎不支持（需依赖第三方中间件） | 原生支持（分片集群 Sharding） |
| 操作难度 | 极复杂：1. 要手动设计分库分表规则（比如按用户 ID 分）；2. 改代码适配中间件（如 Sharding-JDBC）；3. 手动迁移数据，易出现数据倾斜；4. 扩容后维护成本高 | 极简单：1. 新增服务器节点；2. 集群自动把数据分到新节点；3. 客户端无感知，不用改代码；4. 内置均衡器，自动平衡数据 |
| 扩容上限 | 受中间件 / 分表规则限制，一般最多扩到几十台节点 | 线性扩容，支持数百台节点，几乎无上限 |
| 典型场景 | 中小数据量（千万级），扩容频率低 | 大数据量（亿级 / PB 级），需频繁扩容 |
