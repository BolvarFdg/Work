# SpringBoot循环依赖

1. 什么是循环依赖？
    
    循环依赖是指多个bean之间存在相互依赖关系，形成一个闭环的依赖链
    
2. 循环依赖有什么影响？
    - 编译错误
    - bean初始化错误
    - 性能问题：多次解析对象，增加cpu和内存开支
3. spring如何解决循环依赖？
    
    Spring通过三级缓存来解决循环依赖问题：
    
    - 一级缓存（singletonObjects）：用于存储完全初始化好的bean
    - 二级缓存（earlySingletonObjects）：用于存储提前暴露的bean，尚未完全初始化
    - 三级缓存（singletonFactories）：用于存储bean工厂对象，可以生成相应的代理对象

1. 为什么要三级缓存？二级缓存能否解决循环依赖？
    - 二级缓存理论上可以解决，但是会破坏AOP设计
    - AOP代理是在bean初始化阶段完成的，如果没有三级缓存，那放入二级缓存时（属性注入阶段）就要生成AOP代理对象，不符合spring设计，三级缓存中的工厂会返回一个临时对象并非代理对象，最终代理对象会重新生成
    - 三级缓存即解决了循环依赖，又没有破坏spring设计原则
2. 没有二级缓存行不行？只有一三级缓存？
    - 不行
    - 三级缓存中的工厂每次都会返回一个新对象，没有二级缓存会导致生成对象过多，二级缓存就是解决这个问题的
3. 哪种情况下循环依赖可以被解决？
    
    spring能解决单例（singleton）作用域下的setter注入方式的循环依赖，有代理不行
    

| A | B |  |
| --- | --- | --- |
| 属性注入B | 属性注入A | ✅ |
| setter | setter | ✅ |
| 构造器 | 属性注入 | ✅ |
| 构造器 | 构造器 | ❌ |
| AOP | AOP | ❌ |
