# 面向对象三大特征

面向对象编程（OOP）的三大核心特征是**封装、继承和多态**。它们是构建灵活、可维护、可扩展软件系统的基石。以下从设计思想、实现原理、实际应用及代码示例等方面进行详细解析：

---

### 一、封装（Encapsulation）

### **核心思想**

将数据（属性）和操作数据的方法（行为）绑定在一个逻辑单元（类）中，并对外隐藏实现细节，仅通过受控接口与外界交互。

### **核心目的**

1. **安全性**：防止外部直接访问或修改内部数据，避免非法操作。
2. **简化复杂性**：用户无需关心内部实现，只需关注接口功能。
3. **代码可维护性**：内部修改不影响外部调用，降低耦合。

### **实现机制**

- **访问修饰符**：通过 `private`、`protected`、`public` 控制访问权限。
- **Getter/Setter 方法**：提供受控的数据读写方式，可添加校验逻辑。
- **模块化**：将相关功能集中到类中，实现高内聚。

### **代码示例**

```java
public class BankAccount {
    private String accountNumber; // 私有属性，外部不可见
    private double balance;

    // 公有方法提供受控访问
    public void deposit(double amount) {
        if (amount > 0) balance += amount;
    }

    public double getBalance() {
        return balance; // 只读访问，不可直接修改
    }
}

// 使用
BankAccount account = new BankAccount();
account.deposit(1000); // 通过方法操作数据
System.out.println(account.getBalance()); // 合法访问

```

### 二、继承（Inheritance）

### **核心思想**

子类自动获得父类的属性和方法，并可以扩展或重写父类功能，形成类之间的层次关系。

### **核心目的**

1. **代码复用**：避免重复编写公共代码。
2. **逻辑分层**：通过 `is-a` 关系组织类结构（如 `Dog` 是 `Animal`）。
3. **多态支持**：为多态提供基础（见第三部分）。

### **实现机制**

- **单继承**：一个子类只能有一个父类（Java、C#）。
- **多继承**：一个子类可以有多个父类（C++、Python）。
- **方法重写（Override）**：子类重新定义父类方法。
- **super 关键字**：显式调用父类方法或构造函数。

### **代码示例**

```java
class Animal {
    protected String name; // 允许子类访问

    public void eat() {
        System.out.println(name + " is eating.");
    }
}

class Dog extends Animal {
    public Dog(String name) {
        this.name = name;
    }

    @Override // 重写父类方法
    public void eat() {
        super.eat(); // 调用父类方法
        System.out.println("Dog-specific eating behavior.");
    }

    public void bark() {
        System.out.println("Woof!");
    }
}

// 使用
Dog dog = new Dog("Buddy");
dog.eat(); // 输出父类和子类逻辑
dog.bark(); // 子类特有方法

```

### 三、多态（Polymorphism）

### **核心思想**

同一操作作用于不同对象时，可以有不同的解释和执行结果。多态分为**编译时多态**（静态）和**运行时多态**（动态）。

### **核心目的**

1. **接口统一**：不同对象通过相同接口调用。
2. **灵活扩展**：新增子类无需修改现有代码。
3. **解耦**：调用方依赖抽象而非具体实现。

### **实现机制**

1. **方法重载（Overload）**：同一类中同名方法参数不同（编译时多态）。
2. **方法重写（Override）+ 向上转型**：父类引用指向子类对象（运行时多态）。
3. **接口/抽象类**：定义规范，由子类实现具体逻辑。

### **代码示例**

```java
// 抽象类定义接口
abstract class Shape {
    public abstract double calculateArea();
}

class Circle extends Shape {
    private double radius;

    public Circle(double r) { radius = r; }

    @Override
    public double calculateArea() {
        return Math.PI * radius * radius;
    }
}

class Rectangle extends Shape {
    private double width, height;

    public Rectangle(double w, double h) {
        width = w; height = h;
    }

    @Override
    public double calculateArea() {
        return width * height;
    }
}

// 多态调用
public class Test {
    public static void main(String[] args) {
        Shape s1 = new Circle(5);    // 向上转型
        Shape s2 = new Rectangle(4, 6);

        printArea(s1); // 输出圆的面积
        printArea(s2); // 输出矩形面积
    }

    // 统一处理所有Shape子类
    public static void printArea(Shape shape) {
        System.out.println("Area: " + shape.calculateArea());
    }
}

```

### **多态原理（动态绑定）**

- **编译时**：编译器检查父类是否有 `calculateArea()` 方法。
- **运行时**：JVM 根据对象实际类型调用对应方法（通过虚方法表实现）。

---

### 三者的协同关系

1. **封装**是基础：确保类的独立性。
2. **继承**建立层次结构：为多态提供前提。
3. **多态**提升灵活性：基于继承和封装实现统一接口调用。

### **设计原则关联**

- **开闭原则**：通过多态扩展功能，无需修改已有代码。
- **里氏替换原则**：子类必须能替换父类，保证继承合理性。
- **依赖倒置原则**：高层模块依赖抽象接口，通过多态实现解耦。

---

### 常见误区与注意事项

1. **过度继承**：优先使用组合而非继承（防止“钻石问题”）。
2. **破坏封装**：避免通过反射等机制绕过访问控制。
3. **滥用多态**：不必要的多态会增加复杂度。

通过深入理解这三大特征，开发者可以设计出高内聚、低耦合、易扩展的面向对象系统。
