# JVM 性能优化

JVM 性能优化是提升 Java 应用吞吐量、降低延迟和避免内存问题的关键。以下是常见的优化手段及实践方法，涵盖内存管理、垃圾回收（GC）、代码优化和工具使用等方面：

---

### **一、内存管理优化**

1. **合理分配堆内存**
    - 通过 `Xms`（初始堆大小）和 `Xmx`（最大堆大小）设置堆内存，避免频繁扩容和 Full GC。
        
        ```bash
        java -Xms2G -Xmx4G -jar app.jar  # 初始堆2G，最大堆4G
        
        ```
        
    - **建议**：初始堆和最大堆设为相同值，避免运行时动态调整引发性能抖动。
2. **优化新生代与老年代比例**
    - 使用 `XX:NewRatio` 调整新生代（Young Gen）与老年代（Old Gen）的比例（默认 `2`，即老年代是新生代的2倍）。
    - 高吞吐应用可增大新生代，短生命周期对象快速回收。
        
        ```bash
        -XX:NewRatio=1  # 新生代:老年代 = 1:1
        
        ```
        
3. **调整 Eden 和 Survivor 区比例**
    - 使用 `XX:SurvivorRatio` 设置 Eden 区与 Survivor 区的比例（默认 `8`，即 Eden:S0:S1 = 8:1:1）。
    - 若对象存活率高，可增大 Survivor 区避免过早晋升到老年代。
        
        ```bash
        -XX:SurvivorRatio=6  # Eden:S0:S1 = 6:1:1
        
        ```
        
4. **直接内存优化**
    - 使用 `XX:MaxDirectMemorySize` 限制堆外内存（如 NIO 使用的 DirectBuffer），避免 OOM。
        
        ```bash
        -XX:MaxDirectMemorySize=1G
        
        ```
        

---

### **二、垃圾回收（GC）调优**

1. **选择合适的垃圾收集器**
    - **高吞吐场景**：`Parallel GC`（默认，适合后端计算型应用）。
    - **低延迟场景**：`G1 GC`（JDK9+ 默认）或 `ZGC`（JDK11+，超大堆和超低延迟）。
    - **示例**：启用 G1 GC
        
        ```bash
        -XX:+UseG1GC
        
        ```
        
2. **调整 GC 参数**
    - **最大停顿时间**：`XX:MaxGCPauseMillis`（G1 默认 200ms）。
        
        ```bash
        -XX:MaxGCPauseMillis=100  # 目标停顿时间100ms
        
        ```
        
    - **并行线程数**：`XX:ParallelGCThreads`（根据 CPU 核数调整）。
    - **并发线程数**：`XX:ConcGCThreads`（G1 并发标记阶段的线程数）。
3. **避免 Full GC**
    - 监控 `System.gc()` 调用，通过 `XX:+DisableExplicitGC` 禁用显式触发。
    - 优化对象分配，减少大对象直接进入老年代（避免 `XX:PretenureSizeThreshold` 设置过小）。
4. **分析 GC 日志**
    - 启用 GC 日志记录，分析停顿时间和频率：
        
        ```bash
        -Xloggc:/path/to/gc.log -XX:+PrintGCDetails -XX:+PrintGCDateStamps
        
        ```
        
    - 工具：使用 `GCViewer` 或 `gceasy.io` 可视化分析日志。

---

### **三、代码层面优化**

1. **减少对象创建**
    - 避免在循环中创建临时对象（如字符串拼接使用 `StringBuilder`）。
    - 使用对象池（如 Apache Commons Pool）复用重量级对象（数据库连接、线程等）。
2. **避免内存泄漏**
    - 长生命周期集合（如缓存）未清理无用对象 → 使用 `WeakHashMap` 或定期清理。
    - 监听器未注销 → 确保事件源和监听器生命周期一致。
3. **合理使用本地方法（Native Code）**
    - JNI 调用不当可能导致内存泄漏或性能问题 → 尽量减少频繁的 JNI 交互。

---

### **四、JIT 编译优化**

1. **方法内联（Inlining）**
    - JIT 自动将小方法内联，减少调用开销。可通过 `XX:InlineSmallCode` 调整阈值。
2. **热点代码检测**
    - JVM 会优化高频执行的代码（热点代码），避免人为过度优化。
3. **逃逸分析**
    - JIT 自动分析对象作用域，栈上分配对象减少 GC 压力（如 `XX:+DoEscapeAnalysis`）。

---

### **五、工具与监控**

1. **JVM 内置工具**
    - **jstat**：监控堆内存、GC 实时状态。
        
        ```bash
        jstat -gc <pid> 1000  # 每秒输出一次GC数据
        
        ```
        
    - **jmap**：生成堆转储（Heap Dump）分析内存分布。
        
        ```bash
        jmap -dump:format=b,file=heap.hprof <pid>
        
        ```
        
    - **jstack**：抓取线程快照，分析死锁或高 CPU 问题。
        
        ```bash
        jstack <pid> > thread.txt
        
        ```
        
2. **可视化工具**
    - **JVisualVM**：监控内存、线程、GC，分析堆转储。
    - **MAT（Memory Analyzer Tool）**：分析内存泄漏，定位支配树。
    - **Arthas**：在线诊断工具，动态跟踪方法调用和性能热点。

### **六、常见场景优化案例**

### **案例1：频繁 Full GC**

- **现象**：老年代占满，频繁 Full GC，应用停顿。
- **原因**：内存泄漏或 Survivor 区过小导致对象过早晋升。
- **解决**：
    1. 分析堆转储，找到泄漏对象（如未关闭的数据库连接）。
    2. 调整 `XX:SurvivorRatio` 和 `XX:MaxTenuringThreshold`，延长对象在新生代的存活时间。

### **案例2：高延迟**

- **现象**：请求响应时间波动大，GC 停顿时间长。
- **解决**：
    1. 切换到低延迟收集器（如 G1 或 ZGC）。
    2. 调整 `XX:MaxGCPauseMillis`，降低单次 GC 停顿目标。

---

### **七、优化步骤总结**

1. **监控**：通过工具（如 Prometheus + Grafana）收集 JVM 指标（GC 时间、堆内存、线程状态）。
2. **分析**：定位瓶颈（内存泄漏、GC 配置不当、锁竞争）。
3. **调优**：调整参数（堆大小、GC 策略）、修复代码问题。
4. **验证**：压测对比优化前后性能（吞吐量、延迟、资源占用）。

### **附：常用 JVM 参数速查表**

| **参数** | **作用** |
| --- | --- |
| `-Xms2G -Xmx2G` | 初始堆和最大堆设为2G，避免动态调整 |
| `-XX:+UseG1GC` | 启用 G1 垃圾收集器 |
| `-XX:MaxGCPauseMillis=200` | 设置 G1 最大停顿时间目标（单位：ms） |
| `-XX:MetaspaceSize=256M` | 元空间初始大小（替代 PermGen） |
| `-XX:+HeapDumpOnOutOfMemoryError` | OOM 时自动生成堆转储文件 |
| `-XX:NativeMemoryTracking=detail` | 跟踪 JVM 本地内存使用情况 |

通过结合监控数据、工具分析和针对性优化，可显著提升 JVM 应用的性能和稳定性。
