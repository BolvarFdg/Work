# 泛型

> Java 泛型（Generics）是 Java 5 引入的一种特性，它允许在定义类、接口和方法时使用类型参数，从而使代码更加通用、类型安全，并减少类型转换的需要。泛型的核心思想是 **参数化类型**，即在使用时指定具体的类型。
> 

# 1. 泛型的作用

1. **类型安全**：在编译时检查类型，避免运行时的类型转换错误。
2. **代码复用**：编写通用的代码，可以适用于多种类型。
3. **减少类型转换**：避免手动进行类型转换，使代码更简洁。

# 2. 泛型的基本语法

泛型通过尖括号 `< >` 定义类型参数，类型参数可以是任何标识符（通常使用单个大写字母，如 `T`、`E`、`K`、`V` 等）。

```jsx
// 定义一个泛型类
class Box<T> {
    private T value;

    public void setValue(T value) {
        this.value = value;
    }

    public T getValue() {
        return value;
    }
}

public class Main {
    public static void main(String[] args) {
        // 使用泛型类，指定类型为 Integer
        Box<Integer> integerBox = new Box<>();
        integerBox.setValue(123);
        System.out.println("Integer value: " + integerBox.getValue());

        // 使用泛型类，指定类型为 String
        Box<String> stringBox = new Box<>();
        stringBox.setValue("Hello");
        System.out.println("String value: " + stringBox.getValue());
    }
}
```

# 3. 泛型方法

除了泛型类，还可以定义泛型方法。泛型方法的类型参数在方法返回值前声明。

```jsx
public class Main {
    // 定义一个泛型方法
    public static <T> void printArray(T[] array) {
        for (T element : array) {
            System.out.println(element);
        }
    }

    public static void main(String[] args) {
        Integer[] intArray = {1, 2, 3};
        String[] strArray = {"A", "B", "C"};

        // 调用泛型方法
        printArray(intArray);
        printArray(strArray);
    }
}
```

# 4. 泛型接口

泛型接口与泛型类类似，可以在接口中定义类型参数。

```jsx
// 定义一个泛型接口
interface Pair<K, V> {
    K getKey();
    V getValue();
}

// 实现泛型接口
class OrderedPair<K, V> implements Pair<K, V> {
    private K key;
    private V value;

    public OrderedPair(K key, V value) {
        this.key = key;
        this.value = value;
    }

    public K getKey() { return key; }
    public V getValue() { return value; }
}

public class Main {
    public static void main(String[] args) {
        Pair<String, Integer> pair = new OrderedPair<>("Age", 25);
        System.out.println("Key: " + pair.getKey() + ", Value: " + pair.getValue());
    }
}
```

# 5. 泛型的类型擦除

### 1. 什么是范型擦除？

泛型擦除是指在**编译期间**，Java编译器将泛型类型参数（如`<T>`、`<String>`）替换为它们的**原始类型**（通常是`Object`或它们的边界类型），并在必要时插入强制类型转换。这样，编译后的字节码中不再保留泛型类型的具体信息。

```jsx
// 编译前的泛型类
public class Box<T> {
    private T value;
    public void setValue(T value) { this.value = value; }
    public T getValue() { return value; }
}

// 编译后的类（类型擦除后）
public class Box {
    private Object value; // T被替换为Object
    public void setValue(Object value) { this.value = value; }
    public Object getValue() { return value; }
}
```

**关键点：**

- **泛型仅在编译时存在**：编译器会检查泛型类型的一致性（如确保`Box<String>`只能存储`String`）。
- **运行时无泛型信息**：例如，无法通过反射获取`List<String>`的实际类型参数。

### 2. 为什么要范型擦除？

       泛型擦除是Java设计者为了平衡以下目标而做出的决策：

1. **向后兼容性（Backward Compatibility）**

**问题**：Java在引入泛型（Java 5）之前，已有大量使用原始类型（如`List`、`Map`）的代码。如果泛型的实现方式破坏了对旧代码的兼容性，这些代码将无法运行。

**解决方案**：通过泛型擦除，编译后的泛型代码与旧的非泛型代码使用相同的字节码（如`List`在运行时仍然是`List`），从而确保兼容性。

**2. 避免JVM的修改**

**问题**：如果泛型在运行时保留类型信息，需要修改JVM以支持新的泛型类型。

**解决方案**：泛型擦除无需修改JVM，原有JVM（如Java 1.4）可以直接运行泛型代码。

**3. 减少性能开销**

**问题**：如果像C++模板那样为每个泛型类型生成独立的类，会导致代码膨胀（如`List<String>`和`List<Integer>`生成两个类）。

**解决方案**：泛型擦除后，所有泛型类型共享同一个类（如`List`），节省内存和加载时间。

### 3. 范型擦除带来的问题

尽管泛型擦除解决了兼容性和性能问题，但也带来了一些限制：

**1. 无法使用基本类型作为泛型参数**

- 例如，`List<int>`是非法的，必须使用包装类`List<Integer>`。
- **原因**：泛型类型在擦除后变为`Object`，而基本类型无法赋值给`Object`。

**2. 无法在运行时获取泛型类型**

- 例如，以下代码会编译错误：

```jsx
if (list instanceof List<String>) { ... } // 编译错误
```

 **原因**：运行时泛型类型已被擦除，`List<String>`和`List<Integer>`的运行时类型都是`List`。

### 4. 如何绕过范型擦除带来的限制

### **1. 显式传递类型信息**

通过传递`Class<T>`参数，在运行时获取类型信息：

```java
public class Box<T> {
    private T value;
    private Class<T> type;

    public Box(Class<T> type) {
        this.type = type;
    }

    public boolean isType(Object obj) {
        return type.isInstance(obj);
    }
}
```

### **2. 使用反射**

通过反射可以部分获取泛型信息（如方法参数的泛型类型）：

```java
Method method = MyClass.class.getMethod("getList");
Type returnType = method.getGenericReturnType();
if (returnType instanceof ParameterizedType) {
    Type[] typeArgs = ((ParameterizedType) returnType).getActualTypeArguments();
    System.out.println("泛型类型: " + typeArgs[0]); // 输出 String
}
```

### **总结**

| **特性** | **说明** |
| --- | --- |
| **泛型擦除的本质** | 编译时替换泛型类型为原始类型，运行时无泛型信息。 |
| **主要目标** | 兼容旧代码、避免修改JVM、减少性能开销。 |
| **局限性** | 无法使用基本类型、运行时类型信息丢失、无法创建泛型数组等。 |
| **绕过方法** | 显式传递`Class<T>`、使用反射。 |

泛型擦除是Java在历史背景和技术权衡下的产物，尽管存在一些限制，但它仍然是实现泛型安全性和兼容性的有效方案。

# 6. 泛型的通配符

泛型通配符用于表示未知类型，通常用于方法参数中。通配符有以下几种形式：

1. **`<?>`**：表示任意类型。
2. **`<? extends T>`**：表示 `T` 或其子类型（上界通配符）。
3. **`<? super T>`**：表示 `T` 或其父类型（下界通配符）。

```jsx
import java.util.List;

public class Main {
    // 使用上界通配符
    public static double sumOfList(List<? extends Number> list) {
        double sum = 0.0;
        for (Number num : list) {
            sum += num.doubleValue();
        }
        return sum;
    }

    // 使用下界通配符
    public static void addNumbers(List<? super Integer> list) {
        for (int i = 1; i <= 5; i++) {
            list.add(i);
        }
    }

    public static void main(String[] args) {
        List<Integer> intList = List.of(1, 2, 3);
        System.out.println("Sum of intList: " + sumOfList(intList));

        List<Number> numberList = new ArrayList<>();
        addNumbers(numberList);
        System.out.println("Number list: " + numberList);
    }
}
```

# 7. 泛型的限制

1. **不能使用基本类型**：泛型类型参数必须是引用类型，不能是基本类型（如 `int`、`char` 等）。
2. **不能创建泛型类型的实例**：例如 `new T()` 是不允许的。
3. **不能创建泛型数组**：例如 `new T[10]` 是不允许的。
4. **静态成员不能使用类型参数**：因为类型参数与实例相关，而静态成员属于类。

# 8. 泛型的最佳实践

1. **尽量使用泛型**：提高代码的类型安全性和可读性。
2. **避免使用原始类型**：例如 `List` 应改为 `List<String>`。
3. **合理使用通配符**：在需要灵活处理多种类型时使用通配符。
4. **避免过度复杂的泛型设计**：保持代码简洁易懂。

# 总结

Java 泛型通过参数化类型，使代码更加通用、类型安全，并减少了类型转换的需要。泛型可以应用于类、接口和方法，并通过类型擦除在编译时实现。合理使用泛型可以显著提高代码的质量和可维护性。
